# Список дел: Express, TypeScript и PostgreSQL

Веб-приложение для управления списком дел на **Node.js**, **TypeScript**, **Express** и **PostgreSQL**. Поддерживает просмотр задач выбранного набора (`runId`), добавление, переименование, отметку выполнения и удаление. Веб-интерфейс реализован на чистом HTML, CSS и JavaScript без фронтенд-фреймворков. После ввода Bearer-токена интерфейс загружает профиль автора (`GET /api/author/`) и список задач (`GET /api/tasks/?runId=...`). Токен хранится только в оперативной памяти страницы.

## Архитектура и поведение

Серверная часть написана на строгом TypeScript (`tsconfig.json`) и разделена на точку входа (`server.ts`), настройку Express-приложения (`src/app.ts`) и модуль подключения к БД (`src/db.ts`). Маршрутизация использует строгую проверку завершающего слеша (`strict routing`), чтобы все конечные точки строго соответствовали контракту. Публичный маршрут `GET /login/` отдает логин автора в формате `text/plain` без авторизации. Все маршруты `/api/` защищены проверкой `Authorization: Bearer <token>` с постоянным по времени сравнением SHA-256 хешей и заголовком `Cache-Control: no-store`. Логин (`nikita`) и ФИО (`Никифоров Никита Сергеевич`) задаются переменными окружения при старте сервера и никогда не принимаются из тела HTTP-запросов.

Входящие данные проходят строгую валидацию до обращения к PostgreSQL: проверяются формат UUID в параметре пути, допустимые символы и длина `runId` (1–64 символа из `A-Z`, `a-z`, `0-9`, `_`, `-`), длина названия задачи `title` после `trim()` (1–200 символов без нулевых байтов), а также строгий логический тип поля `done`. Запросы с лишними полями, некорректным JSON или пустым телом `PATCH` отклоняются со статусом `400`. При недоступности базы данных возвращается статус `503` и JSON-объект вида `{"error": "..."}`.

При каждом HTTP-запросе сервер обращается напрямую к таблице `todo.tasks` через параметризованные SQL-запросы пула `pg` (до 5 соединений), поэтому изменения, внесенные в базу сторонним клиентом, немедленно отражаются в ответах API, а состояние полностью сохраняется после перезапуска сервера. Поля `id`, `owner_login`, `done` (по умолчанию `false`) и `created_at` генерируются на стороне PostgreSQL. Выборка всегда ограничена логином владельца и отсортирована по времени создания и UUID. При частичном обновлении (`PATCH`) SQL-выражение `COALESCE` сохраняет неизменяемое поле, позволяя обновлять название и статус независимо.

Для развертывания выбрана связка **Render Web Service** (Express) и **Supabase Free** (PostgreSQL). Постоянный бесплатный тариф Supabase предоставляет 500 МБ хранилища и позволяет настроить отдельную ограниченную роль `todo_checker` для независимой проверки преподавателем через SQL (`db/grants.sql`), не раскрывая административные учетные данные. Поскольку бесплатный тариф Render и многие локальные сети не поддерживают IPv6, для подключения к базе используется Session Pooler Supabase (IPv4).

Для воспроизводимой проверки предусмотрен скрипт `scripts/verify.ts`, который тестирует HTTP-контракт, валидацию, создание задачи, обновление и удаление в обе стороны — через API и напрямую в PostgreSQL под ролью проверяющего — с использованием изолированного `runId`, не затрагивающего набор `manual`.

## Схема данных и сопоставление полей

| Поле API | Столбец PostgreSQL | Тип и ограничения |
| --- | --- | --- |
| `id` | `id` | `uuid`, первичный ключ (`gen_random_uuid()`) |
| `ownerLogin` | `owner_login` | `text NOT NULL`, логин автора из конфигурации |
| `title` | `title` | `text NOT NULL`, длина после `trim()` от 1 до 200 символов |
| `done` | `done` | `boolean NOT NULL DEFAULT false` |
| `runId` | `run_id` | `text NOT NULL`, 1–64 символа (`A-Z`, `a-z`, `0-9`, `_`, `-`) |
| `createdAt` | `created_at` | `timestamptz NOT NULL DEFAULT now()`, в JSON отдается в UTC ISO 8601 |

## Установка, инициализация и запуск

Целевые версии: **Node.js 24.x** (минимум 22.x) и **PostgreSQL 17**.

```sh
npm ci
npm run build
cp .env.example .env
# Заполните MOODLE_LOGIN, MOODLE_FULL_NAME, API_TOKEN, DATABASE_URL в .env
npm run db:init
```

Создание ролей и выдача ограниченных прав проверяющему в PostgreSQL:

```sql
CREATE ROLE todo_app LOGIN PASSWORD '<пароль_приложения>';
CREATE ROLE todo_checker LOGIN PASSWORD '<пароль_проверяющего>';
```

Применение прав из `db/grants.sql` и запуск сервера:

```sh
psql "$DATABASE_ADMIN_URL" -v ON_ERROR_STOP=1 -f db/grants.sql
npm start
```

Сквозная проверка HTTP-контракта и двусторонней работы с БД:

```sh
npm run verify
```
